* Limits

- Block sync is one block per request. A gap is walked back one block at a time
  while the chain keeps growing, and peers keep 512 committed blocks
  (=diem/ledger.go:History=). In the sim, a replica that misses 256 consecutive
  proposals or more never catches up; that needs state sync.
- =highest_vote_round= is not persisted. =diem/pacemaker.go:LocalTimeoutRound= has
  no =save_consensus_state()=, so a restarted replica can vote twice in a round.
- Leaders rotate round-robin only. The paper's reputation election (3.7) is left
  out, so a crashed replica costs three rounds in every rotation: its own two, and
  the one before, whose votes go to it. The reputation code is on the branch
  =archive/reputation-leader=.
- Keys are seeded. With =-insecure-seeded-keys=, every replica derives the same
  insecure key set (=diemcrypto/ecdsa.go:SeededKeys=), and replicas talk without
  TLS, so the sender of a message is only claimed.
- TLS certificates are static. With =-keys= and with =-local=, Gorums
  authenticates each peer by its certificate ([[https://github.com/relab/gorums/issues/325][relab/gorums#325]]), and a message
  whose =sender= is not that peer is dropped (=diemnet/server.go:accept=). Each
  certificate is self-signed over the replica's signing key
  (=diemcrypto/tls.go=) and fixed when the keys are made, with no rotation or
  revocation.
- No equivocation evidence. Conflicting messages from one replica are not
  recorded or reported.
